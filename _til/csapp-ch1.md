CSAPP ch1.
컴퓨터 시스템 : 하드웨어 + 시스템 소프트웨어  

>> 컴파일 : 어떤 언어로 쓰인 프로그램을 다른 언어의 동등한 프로그램으로 번역하는 것  
>>  - C언어 프로그램을 기계어로 변환하는 과정 소개  
>>  - 전처리->컴파일->어셈블->링크  
>>	- 다음 hello.c 파일을 기준으로 설명하겠다  

>>		#include <stdio.h>
>>		int main(){
>>			printf(“hello, world!\n”);
>>			return 0;
>>		}


>> 1.  전처리 : .c 소스 텍스트 -> 전처리된 소스 텍스트(.i)  
	ㄴ 컴파일 이전의 순수한 텍스트 변환 단계. #으로 시작하는 지시자만 처리  
	ㄴ #includ <>의 경우 해당 헤더 파일의 내용을 그 자리에 통째로 복사 붙여넣기 한다  
	ㄴ gcc -E hello.c -o hello.i  
>>		
>>2. 컴파일 : 전처리된 C 코드(.i) -> 어셈블리 텍스트(.s)  
	ㄴ 툴체인에서 가장 지능적인 단계이며, 실제로 "언어를 이해"하는 유일한 단계  
	ㄴ 어휘 분석: 텍스트를 토큰(키워드, 식별자, 연산자, 리터럴)으로 쪼갭니다  
  ㄴ구문 분석: 토큰 열을 문법 규칙에 맞춰 트리 구조(AST)로 만듭니다. 문법 오류(세미콜론 누락 등)가 여기서 잡힙니다  
  ㄴ 의미 분석: 타입 검사, 선언되지 않은 변수 검사 등. int에 포인터를 대입하면 경고가 나오는 단계입니다  
  ㄴ 최적화: 죽은 코드 제거, 상수 접기(3*4를 컴파일 시점에 12로), 루프 최적화 등. -O2 같은 옵션이 여기에 작용합니다  
  ㄴ 코드 생성: 대상 CPU 아키텍처(x86-64, ARM 등)의 어셈블리 명령으로 변환합니다. 변수를 레지스터에 배치하는 결정도 여기서 합니다  
	ㄴ gcc -S hello.i -o hello.s  
>>
>>3. 어셈블 : 어셈블리 텍스트(.s) -> 오브젝트 파일(.o)  
	ㄴ 어셈블리 명령을 기계어 바이트로 바꾸는 거의 1:1 기계적 번역  
	ㄴ 결과물인 오브젝트 파일은 단순한 기계어 덩어리가 아니라 구조화된 파일  
	ㄴ 파일을 실행하기 위해서는 호출 함수의 주소와 같은 재배치 정보가 입력되지 않은 미완성의 실행 불가능한 파일  
	ㄴ gcc -c hello.s -o hello.o
>>
>>4. 링크 : 오브젝트 파일들(.o)+라이브러리 -> 실행 파일  
  ㄴ 여러 오브젝트 파일을 하나로 합치고 어셈블 과정에서 남겨둔 빈칸을 채우는 단계  
	ㄴ gcc hello.o -o hello  

>>	* 모든 컴파일 과정이 이러한 것은 아니다. 어셈블리로 작성한 코드는 고급 언어를 어셈블리로 변환하는 컴파일까지의 단계는 필요하지 않을 것이고 기계어로 직접 실행 파일을 작성하는 것도 가능하다. 또한 고급 언어라 하더라도 Go, Rus, Java 등에는 독립된 전처리 단계가 없고 Java의 JIT 컴파일과 같이 컴파일 과정이 다른 경우도 있다.
